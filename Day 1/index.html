Day 1: Advanced Express.js

Express.js is the most widely used web framework in the Node.js ecosystem. While beginners often start by putting every route in a single server.js file, production backends require structured routers, clear controller responsibilities, deep mastery of request and response objects, safe async handling, and predictable RESTful API design. Today you will learn how Express works under the hood and how to organize scalable APIs from the ground up.

Learning Objectives

By the end of Day 1, you will be able to:

  • Explain the Express.js application lifecycle from server initialization to graceful shutdown.
  • Trace how an incoming HTTP request travels through Express and produces an HTTP response.
  • Organize endpoints cleanly using express.Router() and separate controller functions.
  • Read and validate route parameters (req.params), query parameters (req.query), and JSON request bodies (req.body).
  • Use advanced properties and methods on the req and res objects accurately.
  • Configure Express application settings such as trust proxy, etag, and x-powered-by.
  • Write async route handlers and forward errors safely without crashing the Node.js process.
  • Design clean, consistent RESTful endpoints and build a multi-route Express API.

Prerequisites

Before diving into Day 1, make sure you understand these foundational concepts:

  • Browser JavaScript vs. Node.js Runtime: Browser JavaScript runs inside a user's browser (Chrome, Firefox, Safari) to manipulate the DOM and make network requests via fetch(). Node.js runs on a server machine, allowing JavaScript to open network ports, read files, and talk to databases. Express.js runs exclusively on Node.js, never directly inside a web browser.
  • Basic JavaScript ES6+ Syntax: Variables (const, let), arrow functions, destructuring, modules (import/export or require), and async/await.
  • HTTP Basics: Understanding HTTP methods (GET, POST, PUT, PATCH, DELETE), URLs, headers, and status codes (200, 201, 400, 404, 500).
  • Node.js & npm Installed: Ability to run commands like npm init -y and node server.js in your terminal.

Important Terminology and Definitions

Express Application (app)

The core object created by calling express(). It holds application settings, mounts middleware and routers, and listens for HTTP connections or connects to Node's HTTP server.

Express Router (express.Router())

A mini, isolated routing system that acts like a modular sub-application. Routers group related endpoints (for example, all /api/v1/courses routes) into separate files.

Route Handler / Controller

A function that receives (req, res, next) for a matched URL and HTTP method, processes inputs, coordinates with data services, and sends the response.

Request Object (req)

An enhanced Node.js http.IncomingMessage object representing the client's HTTP request, including URL paths, headers, parameters, query strings, and parsed body data.

Response Object (res)

An enhanced Node.js http.ServerResponse object used to set status codes, attach headers, and send JSON, text, files, or redirects back to the client.

RESTful API

An architectural style for APIs that models data as resources (like /users or /orders), uses standard HTTP methods to act on them, and communicates via stateless JSON payloads.

Detailed Theory and Explanations

1. Review of Express.js Fundamentals

Node.js includes a built-in http module that can create web servers, but using it directly requires manually parsing URL strings, collecting raw data chunks from streams for request bodies, checking HTTP methods with nested if statements, and manually setting content-type headers. Express.js is a minimal, unopinionated web framework built on top of Node's http module that automates these repetitive tasks while keeping full access to the underlying Node.js primitives.

2. Express Application Lifecycle

Understanding when things happen in an Express app prevents subtle startup and shutdown bugs. An Express application goes through four distinct phases:

  1. Configuration & Setup Phase: You load environment variables, create the Express instance (const app = express()), apply settings with app.set(), and register global middleware (such as express.json()).
  2. Route Mounting Phase: You connect feature routers to base URL prefixes using app.use('/api/v1/courses', courseRouter), followed by a 404 fallback handler and an error-handling middleware at the very end.
  3. Listening Phase: Calling app.listen(PORT) internally wraps app with Node's http.createServer(app) and opens a TCP port to accept incoming client connections continuously.
  4. Graceful Shutdown Phase: When the server receives termination signals like SIGINT (Ctrl+C) or SIGTERM (from hosting platforms), calling server.close() stops accepting new requests, lets active requests finish, and closes database connections cleanly.

3. How Express Handles Requests and Responses

When a client (like a browser running fetch(), a mobile app, or Postman) sends an HTTP request to your server, Node.js parses the raw TCP stream into an incoming request and a response stream. Express wraps those streams into req and res and pushes them sequentially through its internal stack of registered layers (middleware and routes) in the exact order they were registered in your code.

Each layer checks whether the incoming request matches its path prefix and HTTP method. If it matches, Express runs that layer's callback function. The cycle ends only when a handler calls a terminating method such as res.json(), res.send(), res.sendStatus(), or res.end(). If a handler forgets to send a response and forgets to call next(), the client request hangs indefinitely until it times out.

4. Request and Response Objects in Depth

Knowing the exact properties of req and res allows you to handle any HTTP interaction cleanly:

Property / Method Purpose Example Value / Usage
req.params Captures dynamic named segments defined in the route path. Route /courses/:courseId with URL /courses/42 gives { courseId: "42" }
req.query Parses key-value pairs after the ? in the URL. Always strings by default. URL /courses?level=beginner&limit=10 gives { level: "beginner", limit: "10" }
req.body Holds parsed payload data sent in POST/PUT/PATCH requests (requires express.json()). { title: "Node Streams", durationHours: 4 }
req.headers / req.get() Reads HTTP headers case-insensitively (e.g., Authorization, Content-Type). req.get('content-type')
req.method & req.originalUrl Reveals the HTTP verb and full original path before router stripping. "POST" and "/api/v1/courses?active=true"
req.ip Client IP address (respects trust proxy setting behind reverse proxies). "203.0.113.19"
res.status(code) Sets the HTTP status code and returns res so methods can be chained. res.status(201).json({ data: createdCourse })
res.json(data) Serializes JS objects/arrays to JSON, sets Content-Type: application/json, and ends the response. res.json({ status: "success", data: courses })
res.set(header, val) Sets a custom HTTP response header before sending the body. res.set('Cache-Control', 'no-store')
res.sendStatus(code) Sets status code and sends its standard text message (useful for 204 No Content). res.sendStatus(204)

5. Routers, Application-Level vs. Router-Level Organization

In a real backend, you do not put 50 endpoints inside app.js. Instead, you separate application-level organization (creating app, applying global settings, parsing JSON, mounting top-level path prefixes) from router-level organization (feature modules created with express.Router()).

When you mount a router at app.use('/api/v1/courses', courseRouter), Express strips /api/v1/courses inside courseRouter. Inside courseRouter, router.get('/') matches GET /api/v1/courses, and router.get('/:id') matches GET /api/v1/courses/123. You can also use router.route('/:id') to chain .get(), .patch(), and .delete() on the same path without repeating the path string.

6. Controller Responsibilities

A router file should only map URLs and HTTP methods to controller functions. It should not contain complex calculations, validation loops, or database queries directly. A controller has a clear, focused job:

  • Extract and validate inputs from req.params, req.query, and req.body.
  • Call data layer or service logic to read or update state.
  • Format a consistent JSON response with the appropriate HTTP status code.
  • Pass unexpected errors forward using next(error).

7. Express Settings and Configuration

Express provides built-in configuration switches controlled via app.set(key, value), app.enable(key), and app.disable(key):

  • app.disable('x-powered-by'): Removes the default X-Powered-By: Express response header so attackers do not immediately know your server framework.
  • app.set('trust proxy', 1): Essential when deploying behind reverse proxies like Nginx, Cloudflare, Render, or Railway so req.ip and req.protocol reflect the real client instead of the local proxy.
  • app.set('json spaces', 2): Optional formatting for readable JSON in development (avoid in production to save bandwidth).
  • app.set('case sensitive routing', false) and app.set('strict routing', false): Controls whether /Courses and /courses/ behave identically to /courses.

8. Async Route Handlers and Error Flow

In real backends, nearly every controller talks to a database or external service asynchronously using async/await. In Express 4, if an async route handler throws an error or rejects a Promise without a try/catch block, Express 4 does not catch it automatically—the promise rejection remains unhandled, leaving the request hanging and potentially crashing Node.js.

To handle async errors reliably in Express 4 (and maintain clean code in Express 5 as well), wrap async logic in try/catch and call next(error), or wrap controller functions with an asyncHandler higher-order helper that catches rejected promises and passes them to next(error) automatically.

9. RESTful Route Design

RESTful APIs use nouns (plural resource names) in URLs and HTTP methods for actions. Avoid action verbs in URLs like /getAllCourses or /deleteCourseById.

HTTP Method Endpoint Action Typical Success Status
GET /api/v1/courses Retrieve a list of courses (supports filtering via query params) 200 OK
GET /api/v1/courses/:id Retrieve a single course by ID 200 OK
POST /api/v1/courses Create a new course resource 201 Created
PATCH /api/v1/courses/:id Partially update specific fields of a course 200 OK
PUT /api/v1/courses/:id Replace an entire course resource 200 OK
DELETE /api/v1/courses/:id Delete a course resource 200 OK or 204 No Content

Step 2: Create an Async Handler Utility

This small helper prevents repetitive try/catch blocks in every async controller while guaranteeing rejected promises reach Express error handling.

Backend Source Code: utils/asyncHandler.js

export const asyncHandler = (fn) => {
  return (req, res, next) => {
    Promise.resolve(fn(req, res, next)).catch(next);
  };
};

Step 3: Create the Controller with Input Validation & Proper Status Codes

Notice how the controller handles req.query filtering, req.params lookup, and req.body validation cleanly, and uses async/await to simulate asynchronous storage access.

Backend Source Code: controllers/workshopController.js

import { asyncHandler } from '../utils/asyncHandler.js';

let workshops = [
  { id: 1, title: 'Express Routing Deep Dive', level: 'intermediate', seats: 25 },
  { id: 2, title: 'Node.js Streams & Buffers', level: 'advanced', seats: 18 }
];

const findWorkshopAsync = async (id) => {
  return workshops.find((item) => item.id === id) || null;
};

export const getAllWorkshops = asyncHandler(async (req, res) => {
  const { level } = req.query;

  let results = workshops;
  if (level) {
    const normalizedLevel = String(level).trim().toLowerCase();
    results = workshops.filter((w) => w.level === normalizedLevel);
  }

  res.status(200).json({
    status: 'success',
    count: results.length,
    data: results
  });
});

export const getWorkshopById = asyncHandler(async (req, res) => {
  const id = Number(req.params.id);

  if (!Number.isInteger(id) || id <= 0) {
    return res.status(400).json({
      status: 'fail',
      message: 'Workshop ID must be a positive integer.'
    });
  }

  const workshop = await findWorkshopAsync(id);
  if (!workshop) {
    return res.status(404).json({
      status: 'fail',
      message: `No workshop found with ID ${id}.`
    });
  }

  res.status(200).json({
    status: 'success',
    data: workshop
  });
});

export const createWorkshop = asyncHandler(async (req, res) => {
  const { title, level, seats } = req.body;

  if (typeof title !== 'string' || title.trim().length < 3) {
    return res.status(400).json({
      status: 'fail',
      message: 'Title is required and must be at least 3 characters long.'
    });
  }

  const allowedLevels = ['beginner', 'intermediate', 'advanced'];
  if (!allowedLevels.includes(level)) {
    return res.status(400).json({
      status: 'fail',
      message: 'Level must be beginner, intermediate, or advanced.'
    });
  }

  const parsedSeats = Number(seats);
  if (!Number.isInteger(parsedSeats) || parsedSeats < 1 || parsedSeats > 500) {
    return res.status(400).json({
      status: 'fail',
      message: 'Seats must be an integer between 1 and 500.'
    });
  }

  const nextId = workshops.length > 0 ? Math.max(...workshops.map((w) => w.id)) + 1 : 1;
  const newWorkshop = {
    id: nextId,
    title: title.trim(),
    level,
    seats: parsedSeats
  };

  workshops.push(newWorkshop);

  res.status(201).json({
    status: 'success',
    data: newWorkshop
  });
});

export const updateWorkshop = asyncHandler(async (req, res) => {
  const id = Number(req.params.id);
  if (!Number.isInteger(id) || id <= 0) {
    return res.status(400).json({
      status: 'fail',
      message: 'Invalid workshop ID.'
    });
  }

  const workshop = await findWorkshopAsync(id);
  if (!workshop) {
    return res.status(404).json({
      status: 'fail',
      message: `No workshop found with ID ${id}.`
    });
  }

  const { title, level, seats } = req.body;
  if (title !== undefined) {
    if (typeof title !== 'string' || title.trim().length < 3) {
      return res.status(400).json({ status: 'fail', message: 'Title must be at least 3 characters.' });
    }
    workshop.title = title.trim();
  }

  if (level !== undefined) {
    const allowedLevels = ['beginner', 'intermediate', 'advanced'];
    if (!allowedLevels.includes(level)) {
      return res.status(400).json({ status: 'fail', message: 'Invalid workshop level.' });
    }
    workshop.level = level;
  }

  if (seats !== undefined) {
    const parsedSeats = Number(seats);
    if (!Number.isInteger(parsedSeats) || parsedSeats < 1 || parsedSeats > 500) {
      return res.status(400).json({ status: 'fail', message: 'Seats must be between 1 and 500.' });
    }
    workshop.seats = parsedSeats;
  }

  res.status(200).json({
    status: 'success',
    data: workshop
  });
});

export const deleteWorkshop = asyncHandler(async (req, res) => {
  const id = Number(req.params.id);
  const index = workshops.findIndex((w) => w.id === id);

  if (index === -1) {
    return res.status(404).json({
      status: 'fail',
      message: `No workshop found with ID ${id}.`
    });
  }

  workshops.splice(index, 1);
  res.status(204).send();
});

Step 4: Create Dedicated Feature Routers

Backend Source Code: routes/workshopRoutes.js

import express from 'express';
import {
  getAllWorkshops,
  getWorkshopById,
  createWorkshop,
  updateWorkshop,
  deleteWorkshop
} from '../controllers/workshopController.js';

const router = express.Router();

router.route('/')
  .get(getAllWorkshops)
  .post(createWorkshop);

router.route('/:id')
  .get(getWorkshopById)
  .patch(updateWorkshop)
  .delete(deleteWorkshop);

export default router;

Step 5: Configure the Express Application (app.js) and Server Entry (server.js)

Separating app.js from server.js keeps Express configuration independent from TCP port binding, which also makes automated testing much easier later.

Backend Source Code: app.js

import express from 'express';
import healthRoutes from './routes/healthRoutes.js';
import workshopRoutes from './routes/workshopRoutes.js';

const app = express();

app.disable('x-powered-by');
app.set('trust proxy', 1);

app.use(express.json({ limit: '10kb' }));
app.use(express.urlencoded({ extended: true, limit: '10kb' }));

app.use('/api/v1/health', healthRoutes);
app.use('/api/v1/workshops', workshopRoutes);

app.all('*', (req, res) => {
  res.status(404).json({
    status: 'fail',
    message: `Cannot ${req.method} ${req.originalUrl} on this server.`
  });
});

app.use((err, req, res, next) => {
  const statusCode = err.statusCode || 500;
  res.status(statusCode).json({
    status: 'error',
    message: process.env.NODE_ENV === 'production' ? 'Internal server error' : err.message
  });
});

export default app;

Backend Source Code: server.js

import 'dotenv/config';
import app from './app.js';

const PORT = Number(process.env.PORT) || 5000;

const server = app.listen(PORT, () => {
  console.log(`Server running in ${process.env.NODE_ENV || 'development'} mode on port ${PORT}`);
});

const shutdown = (signal) => {
  console.log(`${signal} received. Shutting down gracefully.`);
  server.close(() => {
    process.exit(0);
  });
};

process.on('SIGINT', () => shutdown('SIGINT'));
process.on('SIGTERM', () => shutdown('SIGTERM'));

Real-World Use Cases

1. SaaS Multi-Resource Backends

A project-management platform separates endpoints into /api/v1/workspaces, /api/v1/tasks, and /api/v1/billing routers so different backend engineers can maintain features independently without merge conflicts in a single massive file.

2. E-Commerce Product Filtering

Product listing endpoints inspect req.query (e.g., ?category=laptops&inStock=true) while product detail endpoints read req.params.productId and return 404 if an item is discontinued.

3. Health Check Probes in Cloud Hosting

Load balancers on AWS, Render, or Kubernetes ping GET /api/v1/health every few seconds. If the Express app responds with 200 OK, traffic continues flowing; if it fails, the host restarts the container safely.

4. Graceful Deployments Without Dropped Users

When deploying a new version of an API, handling SIGTERM with server.close() ensures in-flight checkout requests complete properly before the old Node process exits.

Common Mistakes, Security Notes, and Best Practices

Common Mistakes to Avoid

  • Calling res.json() twice: Sending a response inside an if block without return causes Express to continue executing and throw ERR_HTTP_HEADERS_SENT. Always write return res.status(400).json(...) when exiting early.
  • Forgetting express.json(): Without registering app.use(express.json()) before your routes, req.body will be undefined.
  • Assuming req.query types: Query parameters are always strings (or arrays/objects if repeated). Always convert and validate numbers or booleans explicitly.
  • Placing wildcard routes before specific routes: Defining GET /users/:id above GET /users/profile treats "profile" as an id! Always register static paths before parameterized paths.
  • Swallowing async errors: Writing an async handler without try/catch or an async wrapper in Express 4 leaves failed requests hanging forever.

Security & Best-Practice Notes

  • Limit JSON payload sizes: Always pass { limit: '10kb' } (or an appropriate limit) to express.json() so attackers cannot exhaust server memory with gigabyte payloads.
  • Disable x-powered-by: Reduce unnecessary server fingerprinting with app.disable('x-powered-by').
  • Validate every input: Never trust req.params, req.query, or req.body blindly. Check types, allowed ranges, and allowed values before processing.
  • Keep secrets in environment variables: Load ports, API keys, and modes through process.env and never commit .env files.
  • Avoid leaking stack traces in production: Check process.env.NODE_ENV before returning detailed error messages to clients.

Short-Answer Questions

Think through each answer carefully before clicking to reveal the model answer.

1. Explain the difference between req.params, req.query, and req.body.

req.params holds dynamic named segments from the URL path (e.g., :id). req.query holds optional key-value pairs after the ? in the URL, commonly used for filtering or sorting. req.body holds structured payload data (such as JSON) sent inside the body of POST, PUT, or PATCH requests after body-parsing middleware runs.

2. Why should routers avoid containing heavy business logic or database queries directly?

Routers are responsible only for mapping HTTP methods and URL paths to controllers. Keeping logic inside controllers (and later services) improves readability, makes code reusable across routes, and simplifies unit testing.

3. What happens during the Express application lifecycle when SIGTERM is handled gracefully?

Instead of killing the Node process immediately and cutting off active users mid-request, server.close() stops accepting new connections, allows existing in-flight HTTP requests to finish sending their responses, closes open resources, and exits cleanly with status 0.

4. Why should express.json() specify a limit option such as { limit: '10kb' }?

Without a payload size cap (or with overly large limits), a malicious client could send huge JSON bodies to consume excessive server RAM and CPU during parsing, causing a denial-of-service condition.

5. What is the difference between req.originalUrl and req.url inside a mounted Express router?

Inside a router mounted at /api/v1/workshops, Express strips the mount prefix from req.url (making it / or /5), whereas req.originalUrl preserves the complete path requested by the client (/api/v1/workshops/5).

Day 1 Revision Summary

  • Express runs on Node.js on the server and wraps Node's http streams into enriched req and res objects.
  • An Express app flows through configuration, route mounting, listening, and graceful shutdown phases.
  • Use express.Router() to split endpoints by feature and delegate request handling to focused controller functions.
  • Always validate req.params, req.query, and req.body, return early after sending error responses, and place static routes before dynamic :param routes.
